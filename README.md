# בקרת בקשות ייצור

מערכת ווב לניהול, מעקב ובקרה על בקשות ייצור במדור — לפי הפורמט המחייב לבקשות ייצור (נוהל יוסי, 16/06/26).

**סטאק:** Next.js (App Router) + Postgres (Neon) על Vercel. תלויות ריצה: `next`, `react`, `pg` בלבד.
הממשק **בנוי קודם לטלפון** בערכת "חמ"ל" כהה. התכנון המלא: [architecture.md](architecture.md) · סקיצות עיצוב: [design/](design/)

## פריסה (Vercel)

1. צרו Postgres ב-[Neon](https://neon.tech) (או דרך Vercel Marketplace) וקחו את ה-`DATABASE_URL`.
2. חברו את ה-repo ל-Vercel והגדירו משתני סביבה:
   - `DATABASE_URL` — מחרוזת החיבור של Neon
   - `SESSION_SECRET` — מחרוזת אקראית ארוכה (`openssl rand -hex 32`)
   - `JOIN_CODE` — קוד ההצטרפות שחברי המדור יזינו בהרשמה
3. זהו. הסכמה נוצרת אוטומטית בפנייה הראשונה ל-DB.

## פיתוח מקומי

```bash
cp .env.example .env.local     # ולמלא DATABASE_URL, SESSION_SECRET, JOIN_CODE
npm install
npm run db:seed                # (אופציונלי) ארבע בקשות דוגמה מהצ'אט המקורי
npm run dev                    # http://localhost:3000
npm test                       # בדיקות לוגיקת הדומיין
```

## מה יש בפנים

- **הזדהות** — חשבונות אישיים (הרשמה עם קוד הצטרפות משותף), סשן בעוגייה חתומה. כל פעולה נרשמת על שם המחובר.
- **תור עבודות** — פיד ממוין לפי דחיפות תג"ב, צ'יפים שהם גם מדדים וגם מסננים, חיפוש, הדגשת חריגות.
- **אכיפת שלמות** — בקשה עם שדות חובה חסרים נקלטת כ"מעוכבת" עם רשימת חוסרים, ומקודמת אוטומטית כשמשלימים.
- **מחזור חיים** — מעוכבת → ממתינה לאישור → מאושרת → בייצור → הושלמה (+ נדחתה/בוטלה).
- **היסטוריה** — נתיב ביקורת מלא, כולל סימון "שינוי אחרי אישור" לשדות מהותיים.
- **ייצוא ל-WhatsApp** — כפתור העתקה בפורמט המחייב, לשיתוף סטטוס חזרה בקבוצה.
